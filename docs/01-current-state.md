# Текущее состояние бота

Документ описывает код в ветке `master` на коммите `03a11fa`. Номера строк относятся к этому коммиту.

## Назначение

Бот ищет в Steam игры с большой скидкой и присылает их в Telegram. Интерактивной части нет: команды не принимаются, вебхука нет. Это периодическая задача, которая только отправляет сообщения.

Несмотря на название репозитория, Steam API не вызывается нигде. Единственный источник данных это Reddit.

## Конфигурация

| Переменная | По умолчанию | Обязательна | Где используется |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | нет | да | bot.py, telegram_client.py |
| `TELEGRAM_CHAT_ID` | нет | да | bot.py, telegram_client.py |
| `DATABASE_PATH` | `data/steam_bot.db` | нет | database.py |
| `MIN_DISCOUNT_PERCENT` | `70` | нет | bot.py |

Значения читаются один раз при импорте. Правка `.env` у работающего процесса ничего не меняет до перезапуска.

`TELEGRAM_CHAT_ID` в рабочем `.env` это личный чат пользователя, а не канал. Бот не может написать пользователю, который его заблокировал или не нажимал /start.

## Хранилище

Один файл SQLite, путь относительный и считается от рабочей директории процесса.

```sql
CREATE TABLE sent_games (
    app_id   TEXT PRIMARY KEY,
    title    TEXT NOT NULL,
    discount INTEGER DEFAULT 0,
    sent_at  TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE sent_events (
    event_name TEXT PRIMARY KEY,
    sent_at    TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

`sent_events` всегда пуста, потому что источник событий не реализован. Соединение открывается заново на каждую операцию, WAL и таймаут ожидания блокировки не настроены.

## Правила повторной отправки

Решение принимает [database.py:84](../database.py#L84). Скидка отправляется, если выполнено любое условие:

1. Игры нет в `sent_games`.
2. С прошлой отправки прошло 7 дней или больше. Порог задан в [bot.py:20](../bot.py#L20).
3. Новая скидка строго больше сохранённой.

Записи старше 90 дней удаляются в конце каждого цикла. Правило 7 дней делает эту чистку почти бесполезной: любая игра, которая остаётся в ленте, и так будет отправлена снова через неделю.

### Мелкие

- [scraper.py:141](../scraper.py#L141): суффикс `on Steam` срезается только в конце строки. В базе лежит `Ghosts 'n Goblins Resurrection on steam (2.99$)`.
- [scraper.py:121](../scraper.py#L121): шаблон `/app/(\d+)` принимает и ссылки на новости вида `/news/app/440/`.
- [scraper.py:239](../scraper.py#L239): на RSS-пути рейтинг Reddit всегда 0, поэтому строка про рейтинг в [telegram_client.py:160](../telegram_client.py#L160) никогда не выводится.
- Нет защиты от одновременного запуска. Ручной `python3 bot.py` рядом с сервисом отправит дубли.
- При первом запуске на пустой базе бот отправит все подходящие скидки из ленты разом, без ограничения.

## Состояние на старом сервере

Старый сервер работал под WSL2 без systemd. Бот там запускался вручную один раз.

| Проверка | Результат |
|---|---|
| Последняя запись в `sent_games` | 15 февраля 2026, 10 строк, скидки от 75 до 90 процентов |
| Каталог `venv` из юнита | отсутствует |
| Пользователь `steam-bot` из юнита | отсутствует |
| Юнит установлен в systemd | нет, systemd не работает |
| Владелец `data/` и базы | root, запись для сервисного пользователя невозможна |
| Зависимости | стояли системно в Python 3.10.12 |

Локальная правка юнита, которая переводила пути на `/var/www/steamfreegamebot`, сохранена отдельным коммитом в этой ветке. В таком виде юнит не запустится. Рабочий вариант описан в [03-hosting.md](03-hosting.md).
